# Chain vectors

Per-device hash chains (#28), each with the verdict every verifier must reach: the phone's core
here, the companion's shore verifier (#62) and burgee. `docs/event-chain.md` is the specification.

## Direction: pro-companion is canonical, burgee vendors

**pro-companion is canonical for this set, and burgee vendors it**, the same direction groom
decision G32 set for the scoring vectors. A change to a vector is made here first, and burgee's copy
follows it. burgee copies this directory unchanged, `SHA256SUMS` included.

## Expected verdicts are decided by hand

Each file's `expected` block was written by hand from `docs/event-chain.md`, beside the change that
makes the case: an alteration, a removal or a gap.
**Expected verdicts are never generated by the verifier they check**, here or anywhere else. A
vector produced by running the verifier would pass that verifier by construction.

The events were written by `packages/core/tool/write_chain_vectors.dart`, from the core's own
serialiser. Two independent implementations checked them when they were made: Python's `hashlib` for
every hash, and Trail of Bits' `rfc8785` package for every canonical text. When a verifier disagrees
with a vector, the vector is re-derived from the specification before either side changes.

## Format: `pro-companion-chain-vector/1`

```
{
  "format": "pro-companion-chain-vector/1",
  "name": "broken-payload",
  "description": "what was done to the chain, in words",
  "events": [ { "hash": "<sha256 of canonical, lowercase hex>", "canonical": "<the event's RFC 8785 text>" } ],
  "expected": { "<device_id>": { "verdict": "intact" | "gapped" | "broken",
                                 "at_seq": 5, "at_ulid": "…", "after_seq": 4 } }
}
```

- **`events`** are the events a verifier holds, in log order, with nothing else about them. The
  hash is over the canonical text exactly as given.
- **`at_seq` and `at_ulid`** appear only on a broken verdict, and name its break point.
  **`after_seq`** appears when that event follows another one. It is the event before the break,
  which may be the altered one.

## Coverage

| Vector | Case | Verdict |
|---|---|---|
| `intact` | a whole day, seq 1–6 | intact |
| `gapped-middle` | seq 3 and 4 not yet arrived | gapped |
| `gapped-start` | seq 1–3 not yet arrived | gapped |
| `broken-payload` | one byte of seq 4's payload altered | broken at 5, after 4 |
| `broken-relinked` | seq 3 removed, the rest re-linked | broken at 4, after 2 |
| `broken-relinked-start` | seq 1 and 2 removed, seq 3 re-linked to genesis | broken at 3 |
| `broken-first-link` | seq 1's previous hash is not genesis | broken at 1 |
| `broken-fork` | two events hold seq 3 | broken at 3, the later ULID |
| `handoff` | a replacement phone's own chain from genesis | intact, per device |
