# Golden scoring vectors

Low-point series scoring cases under Appendix A of the Racing Rules of Sailing 2025–2028, each with
its expected standings. The Dart scorer (#2) is held to them, and so is burgee's engine once it
vendors them.

## Direction: pro-companion is canonical, burgee vendors

**pro-companion is canonical for this set, and burgee vendors it** — groom decision G32 on #12
(2026-09-24), which reverses G19; ADR 005 point 4 as amended by #45. A change to a vector is made
here first, and burgee's copy follows it. burgee copies this directory unchanged, `SHA256SUMS`
included; the drift check that compares its copy against this manifest is held story H87.

## Expected results are computed by hand

Every expected result was worked out by hand from the rule text, and the arithmetic is kept in the
vector's `working` field. **Expected results are never generated by the Dart port** (#2), nor by
burgee's engine or any other scorer. A vector produced by running the code it is meant to check
would pass that code by construction.

When a scorer disagrees with a vector, the vector is re-derived by hand from the rule before either
side changes. Neither side wins by being the one that runs.

## Edition

The rule text is the World Sailing RRS 2025–2028 with its published changes and corrections. The
issues that asked for this set (#2, #83) use the **2021–2024 numbers A4.1 and A4.2**. In 2025–2028,
A4 has no subsections: the points table is **A4**, and "one more than the number of boats entered"
is **A5.2**. The vectors cite the 2025–2028 numbers.

One scoring change between the editions shows up here. **44.3(c)'s 20% scoring penalty is now
rounded to the nearest tenth of a point** (0.05 rounded upward). 2021–2024 rounded it to the nearest
whole number. `scp-scoring-penalty` is built so that the two editions give different standings.

**The code set is burgee's scoring vocabulary** (owner decision on #83, 2026-09-24). That means
the codes its engine scores today — DNC, DNS, DNF, OCS, RET and DSQ — plus the five burgee#15 adds:
RDG, DNE, UFD, BFD and SCP.

**Not covered**:

- the A10 codes outside that vocabulary: ZFP, NSC and DPI;
- A7 ties at the finishing line;
- redress by A9(b) or A9(c), and more than one RDG for one boat;
- a scoring penalty whose number of points the notice of race states;
- a series tie that A8.2 cannot break;
- handicap and rating scoring (A3's corrected times).

A scorer that passes this set can still be wrong in any of those cases.

## Format

One JSON file per case, named by its `id`.

| Field | Meaning |
|---|---|
| `format` | `pro-companion-scoring-vector/1` |
| `id` | the file name without `.json` |
| `description` | what the case shows, in one sentence |
| `rules` | the rules exercised, as `A2.1`, `A9(a)`, `44.3(c)`, `90.3(b)` |
| `citation` | the rule text relied on, naming every rule in `rules` |
| `expected_source` | always `hand` |
| `series.entries` | the boats entered in the series; A5.2's "number of boats entered" is its length |
| `series.discards` | `{"count": N}`, or `{"schedule": [{"races": 4, "count": 1}, …]}`, meaning N scores are excluded once at least `races` races are scored and none below the first threshold |
| `series.a5_3` | whether the notice of race puts A5.3 in force |
| `races[].finishes` | boats in the order they crossed the finishing line, first to last |
| `races[].codes` | boat → `{"code": …}`; an RDG also carries `"redress": "A9(a)"` |
| `expected[]` | one row per boat in rank order: `rank`, `boat`, `races[]` (`points`, `code` where scored under one, `excluded`), `gross` (every race), `net` (the series score) |
| `working` | the hand computation |

Points are whole numbers or tenths. Compare them in tenths, not as floating point.

## Recording conventions the vectors rely on

- **Nothing recorded is DNC.** A boat entered in the series with neither a finish nor a code in a
  race did not come to the starting area. It scores DNC, and the expected row says `DNC` (A2.2).
- **A DNC, DNS, OCS or DNF boat never appears in `finishes`**: she did not start, or did not finish.
- **A DSQ, DNE, UFD, BFD or RET boat may appear in `finishes`**, because she crossed the line
  before being disqualified or retiring. She vacates her place, and every boat behind her moves up
  one (A6.1).
- **An SCP or RDG boat keeps her place.** No other boat's score changes (44.3(c), A6.2).
- **Under A5.3, "came to the starting area" means every boat in the race except a DNC**, whether
  explicit or by nothing recorded.

## Integrity

- `SHA256SUMS` lists every file here except itself, in `sha256sum` format. `sha256sum -c SHA256SUMS`
  run in this directory checks a copy, and it is what burgee's vendored copy is compared against.
  Update it in the same commit as any change here:
  `ls | grep -v '^SHA256SUMS$' | LC_ALL=C sort | xargs sha256sum --text > SHA256SUMS`.
  Keep `--text`. Git Bash on Windows otherwise writes each line in binary form (`<hash> *<name>`),
  which is not the two-space line a Linux `sha256sum` writes, and the test refuses it.
- The hashes are over LF bytes. `.gitattributes` holds this directory at `eol=lf` on every checkout,
  because `core.autocrlf` would otherwise give a Windows checkout different bytes from CI's.
- `test/scoring_vectors_test.dart` fails on:
  - a malformed vector, or one missing its citation or its hand working;
  - arithmetic that does not add up;
  - an expected code that disagrees with the race input;
  - a coverage gap against the table above;
  - a stale `SHA256SUMS`.

  It scores nothing: whether the expected standings are *right* is the hand working's job, and #2's.
